JavaScript I: el lenguaje

JavaScript es la mitad CPU del curso: el bucle de animación, la física, el estado y los datos que mandarás a la GPU. Aquí repasamos el lenguaje justo, pero con lupa: cómo son de verdad sus números, por qué % no es el módulo de GLSL, qué es una referencia, qué captura una closure y por qué this desaparece en el peor momento.

⏱ 90 minRequisitos: 1.1

Al terminar esta lección

  • Conocerás los tipos de JavaScript y las rarezas de typeof, y sabrás elegir entre const, let y var (y qué es la zona muerta temporal).
  • Entenderás que todo número es un double IEEE-754: por qué 0.1 + 0.2 !== 0.3, hasta dónde son exactos los enteros, qué son NaN, -0 e Infinity y qué hace de verdad x | 0.
  • Sabrás que % es un resto con el signo del dividendo y cómo escribir el módulo que usa GLSL.
  • Evitarás las trampas de las conversiones, ==, los valores falsy, las referencias compartidas y el this perdido.
  • Escribirás funciones, closures, desestructuraciones y una clase Particula como las que usarás en el resto del curso.
  • Sabrás por qué crear objetos en cada frame provoca pausas del recolector de basura, y cómo evitarlo.

Por qué repasar JavaScript con lupa

En este curso, JavaScript es el lado CPU del esquema de la lección 0.1: guarda el estado, mide el tiempo, integra la física, aplica el easing y prepara los datos que la GPU va a consumir. Sus fallos típicos no son de sintaxis, que el motor te señala enseguida. Son silenciosos: un NaN que se cuela en una posición y hace desaparecer una partícula sin ningún error, un -1 % 5 que devuelve −1 y rompe un índice cíclico, cien partículas que se mueven a la vez porque comparten un objeto, un this que se pierde al pasar un método a requestAnimationFrame.

Esta lección no es un curso de JavaScript desde cero: supone que sabes qué es una variable, un if y un bucle. Es un repaso de lo que de verdad importa para animar, con cada comportamiento raro medido en Chrome. Todos los editores imprimen en la consola que tienen debajo; úsalos para comprobar cada afirmación.

Valores y tipos

JavaScript tiene siete tipos primitivos (number, string, boolean, undefined, null, bigint y symbol) y un tipo compuesto: object, que incluye los arrays, las funciones y las instancias de clases. Los primitivos son inmutables y se comparan por valor; los objetos se comparan por identidad, algo que veremos con calma porque es fuente de errores. El operador typeof te dice el tipo… casi siempre:

Variables: const, let y var

La regla práctica cabe en una línea: const por defecto, let cuando necesites reasignar, var nunca. Los matices:

  • const impide reasignar la variable, no modificar el objeto al que apunta. const c = 1; c = 2; lanza TypeError: Assignment to constant variable., pero const o = { x: 1 }; o.x = 2; funciona. Una posición en un const se puede mover; lo que no puedes es apuntar la variable a otra posición.
  • let y const tienen ámbito de bloque (entre llaves); var tiene ámbito de función e ignora los bloques.

Y luego está el hoisting («izado»): antes de ejecutar un ámbito, el motor registra todas sus declaraciones. Lo que cambia es qué valor tienen antes de llegar a su línea. Lo medí:

Usar antes de la línea que declara…Resultado
let a = 1; (o const)ReferenceError: Cannot access 'a' before initialization
var v = 1;undefined, sin error (la declaración sube; la asignación, no)
function saluda() {…}funciona: la función entera sube
var saluda = function () {…};TypeError: saluda is not a function (vale undefined)
class P {}ReferenceError: Cannot access 'P' before initialization

El tramo entre el comienzo del bloque y la línea de un let, const o class se llama zona muerta temporal (TDZ): la variable existe, pero tocarla es un error. Es una red de seguridad, no un fastidio: con var, el mismo error pasa desapercibido como un undefined.

Los let, const y class del nivel superior de un <script> clásico viven en un ámbito global compartido por todos los scripts de la página. Lo comprobé con dos scripts que declaraban const lienzo: el segundo falló con SyntaxError: Identifier 'lienzo' has already been declared y no se ejecutó ni una línea suya (el error se detecta antes de ejecutar). Y hay nombres que ya están ocupados por el objeto window:

  • let top = 1; en el nivel superior da el mismo SyntaxError, porque window.top es una propiedad que no se puede redefinir.
  • var top = 5; no da error, pero no hace nada: typeof top siguió siendo "object", la ventana.
  • var name = 123; «funciona»… y name vale el string "123", porque en realidad estás asignando window.name, que convierte todo a texto.

Por eso las librerías (y los archivos de este curso: mira el principio de curso.js) envuelven todo su código en una función que se llama a sí misma, (function () { "use strict"; … })();, que crea un ámbito propio. Otra opción es un simple bloque { … } para los let/const. La solución moderna son los módulos, que tienen ámbito propio… y que no funcionan con file:// (final de la lección).

Síntoma: un script entero no se ejecuta y la consola dice SyntaxError: Identifier 'lienzo' has already been declared (o 'top', 'location'…), aunque en ese archivo solo hay una declaración.

Causa: otro <script> clásico de la página ya declaró ese nombre con let/const/class en su nivel superior, o el nombre es una propiedad fija de window (top, location…). Todos los scripts clásicos comparten el ámbito global.

Solución: envuelve el código de cada script en su propio ámbito, con un bloque { … } o una función autoejecutada (function () { … })(), o renombra la variable.

Números: todos son doubles de 64 bits

En JavaScript solo hay un tipo de número para enteros y decimales: el double IEEE-754 de 64 bits, el mismo que el double de C. Tiene 1 bit de signo, 11 de exponente y 52 de mantisa, lo que da unas 15–17 cifras decimales significativas. Es un formato binario con coma flotante: puede representar exactamente 0.5 o 0.25, pero no 0.1, igual que en decimal no puedes escribir 1/3 con un número finito de cifras. Desmontarás un float bit a bit en la lección 1.6, y la GPU usa una versión más pequeña, de 32 bits, con sus propios problemas (lección 3.7).

0.1 + 0.2 y cómo comparar decimales

0.1 + 0.2 da 0.30000000000000004: ni 0.1 ni 0.2 son exactos, y el error de los dos, sumado y redondeado, se nota en la última cifra. Por eso nunca compares decimales con ===. Otros resultados reales: 1.1 + 2.2 = 3.3000000000000003 y 4.35 * 100 = 434.99999999999994 (así que Math.floor(4.35 * 100) da 434).

La receta que aparece en todas partes es Math.abs(a - b) < Number.EPSILON, con Number.EPSILON = 2.220446049250313e-16. Funciona con 0.1 * 3 frente a 0.3, pero falla con 1.1 + 2.2 frente a 3.3: la diferencia es 4,4 · 10−16, el doble de EPSILON. El motivo: EPSILON es la distancia entre 1 y el siguiente double, y la distancia entre doubles consecutivos crece con el tamaño del número (entre 2 y 4 es el doble que entre 1 y 2; entre 1024 y 2048 es 1024 veces mayor, unos 2,3 · 10−13). Es una tolerancia pensada para valores cercanos a 1, no para cualquier escala.

El Math.max(1, …) convierte la tolerancia en absoluta cerca de cero, donde una tolerancia relativa no tendría sentido.

Enteros exactos… hasta 253

Con 52 bits de mantisa (más uno implícito), un double representa exactamente todos los enteros hasta 253 = 9 007 199 254 740 992. Number.MAX_SAFE_INTEGER vale 253 − 1. A partir de ahí faltan números: 2**53 === 2**53 + 1 da true, y si escribes el literal 9007199254740993, JavaScript lo guarda y lo imprime como 9007199254740992. Para animar no suele importar (performance.now() y Date.now() quedan muy lejos del límite), pero la GPU trabaja con floats de 32 bits, donde el límite de enteros exactos es 224 = 16 777 216. Lo verás al convertir en la lección 1.6.

NaN, -0 e Infinity

NaN (Not a Number) es el resultado de una operación sin sentido: 0 / 0, Math.sqrt(-1), Number("12px"), undefined * 2. Tres propiedades que lo hacen peligroso:

  • No es igual a nada, ni a sí mismo: NaN === NaN da false. Por eso [NaN].indexOf(NaN) da −1, mientras que [NaN].includes(NaN) da true (usa otra comparación).
  • Se propaga: cualquier operación con un NaN da NaN. Una sola velocidad NaN contamina la posición, que contamina todo lo que dependa de ella.
  • Es silencioso: nada lanza un error. ctx.arc() ignora las coordenadas NaN sin decir nada (lo viste en el ejercicio 1.1.3), y un uniform NaN en un shader produce colores imprevisibles.

Para detectarlo, Number.isNaN(x). No uses la función global isNaN, que convierte antes de comprobar: isNaN("hola") da true, pero Number.isNaN("hola") da false (un string no es el valor NaN). Para comprobar que un valor es un número usable, Number.isFinite(x), que rechaza NaN, Infinity y cualquier cosa que no sea un número.

Síntoma: una partícula, un objeto o todo el dibujo desaparece de repente (o nunca aparece), y la consola está limpia.

Causa: un NaN se coló en una posición y se propagó. Los orígenes típicos: dividir por cero al normalizar un vector de longitud 0 (0 / 0), un dt que vale undefined en el primer frame, una propiedad mal escrita (p.vx cuando se llamaba p.velX da undefined, y undefined * dt es NaN) o un string que no se pudo convertir.

Solución: imprime la posición: si ves NaN, sigue hacia atrás hasta la primera operación que lo produjo. Protege las divisiones (const l = Math.hypot(x, y); if (l > 0) { x /= l; y /= l; }) y valida entradas con Number.isFinite. Un console.assert(Number.isFinite(p.x), p) en el bucle lo caza en el acto.

-0 existe: el signo es un bit aparte, y el cero lo tiene. 0 === -0 da true, pero Object.is(0, -0) da false y 1 / -0 da -Infinity. Aparece más de lo que crees: Math.round(-0.4) da -0, y 0 * -5 también. Casi siempre es inofensivo, con dos excepciones que sí te afectarán:

  • Math.atan2(0, -1) da π, pero Math.atan2(-0, -1) da −π. El ángulo salta una vuelta entera según el signo de un cero, algo que desconcierta cuando calculas la dirección de un vector.
  • (-0.04).toFixed(1) da "-0.0", que en una interfaz queda raro. En cambio, String(-0) y JSON.stringify(-0) dan "0", y lo esconden. (La consola de los editores del curso sí escribe -0.)

Infinity sale de dividir por cero (1 / 0) o de pasarse del máximo (1e308 * 10; Number.MAX_VALUE ≈ 1,8 · 10308). Operar con él da resultados razonables hasta que no los da: Infinity - Infinity y 0 * Infinity son NaN.

x | 0: truncar a entero de 32 bits

Los operadores de bits (|, &, ^, ~, <<, >>, >>>) convierten sus operandos a enteros de 32 bits con signo antes de operar. Así que x | 0 (hacer OR con cero, que no cambia ningún bit) es una forma de convertir a entero. Lo que hace exactamente:

ExpresiónResultadoQué ha pasado
3.7 | 0 / -3.7 | 03 / −3trunca hacia cero (no es Math.floor: Math.floor(-3.7) es −4)
NaN | 0, Infinity | 0, "12px" | 00lo que no es un entero finito se convierte en 0, sin avisar
2**31 | 0−2147483648el bit 31 es el de signo: da la vuelta
1e10 | 01410065408se queda con los 32 bits bajos (módulo 232)
Date.now() | 0un número negativo sin sentido (−346922120 en mi prueba)los milisegundos desde 1970 no caben en 32 bits
-1 >>> 04294967295>>> 0 reinterpreta como entero sin signo

Con | 0, >>> 0 y Math.imul (multiplicación entera de 32 bits) puedes hacer en JavaScript la aritmética entera de C, que es la base de los generadores pseudoaleatorios deterministas. El generador mulberry32 que usa assets/js/texturas.js para dibujar las texturas del curso está escrito exactamente así, y de esa idea salen las funciones de hash de los shaders de ruido (lección 6.6). Además, | 0 les dice a los motores JavaScript que un valor es entero, lo que permitía optimizaciones; hoy los motores lo deducen solos casi siempre.

La trampa: | 0 solo es seguro con valores entre −231 y 231 − 1. Fuera de ese rango da números absurdos, sin error. Para truncar valores grandes (marcas de tiempo, índices de muchos millones), usa Math.trunc.

¿Qué imprime console.log(0.1 + 0.2 === 0.3, Number.isNaN("abc"), -7.9 | 0)?

  • false true -8
    Number.isNaN no convierte: un string no es el valor NaN, así que da false (la global isNaN("abc") sí daría true). Y | 0 trunca hacia cero: −7.
  • false false -7
    Exacto. La suma da 0.30000000000000004; Number.isNaN solo es true para el valor NaN; y | 0 trunca hacia cero, como Math.trunc, no hacia abajo como Math.floor.
  • true false -7
    0.1 + 0.2 vale 0.30000000000000004, así que la comparación estricta con 0.3 da false.

% no es el módulo matemático

El operador % de JavaScript es el resto de la división truncada, y su resultado tiene el signo del dividendo (el número de la izquierda):

ExpresiónResultado

El módulo matemático, el que devuelve siempre un valor entre 0 y n, se define con floor en lugar de truncar: a − n · floor(a / n). Así es exactamente como define GLSL su función mod(x, y), que usarás constantemente para repetir patrones (lección 3.4). En JavaScript:

Esta gráfica está dibujada por un shader, es decir, es lo que calcula de verdad la GPU. La primera curva es mod(x, 1.0) de GLSL: un diente de sierra que se repite igual a ambos lados del cero. La segunda, x - trunc(x), es lo que hace el % de JavaScript con x % 1: para x negativa, la sierra se da la vuelta y va de 0 a −1. (Con x positiva las dos curvas coinciden, y por eso solo ves la segunda, en cian, dibujada encima de la primera.)

Síntoma: recorres una paleta de colores o unos fotogramas con (i - 1) % n para ir hacia atrás, y al pasar del primero sale undefined. O un patrón que repites con x % tamaño se ve bien a la derecha del origen y roto (o reflejado) a la izquierda.

Causa: % conserva el signo del dividendo: (0 - 1) % 5 es −1, y colores[-1] es undefined.

Solución: usa un módulo de verdad, ((a % n) + n) % n o a - n * Math.floor(a / n), siempre que el dividendo pueda ser negativo.

¿Cuánto vale -7 % 3 en JavaScript, y cuánto mod(-7.0, 3.0) en GLSL?

  • 2 y 2
    El mod de GLSL sí da 2 (−7 − 3·floor(−7/3) = −7 − 3·(−3) = 2), pero el % de JavaScript conserva el signo del dividendo.
  • −1 y 2
    Correcto. JavaScript trunca la división (−7/3 → −2) y el resto es −7 − 3·(−2) = −1. GLSL usa floor (−7/3 → −3) y da −7 − 3·(−3) = 2, siempre entre 0 y 3.
  • −1 y −1
    El mod() de GLSL está definido con floor, así que con divisor positivo nunca devuelve negativos.

Strings, template literals y conversiones

Los strings son inmutables (s[0] = "x" no hace nada) y están codificados en UTF-16, lo que tiene un efecto curioso: "😀".length es 2, porque el emoji ocupa dos unidades de 16 bits; [..."😀"].length es 1, porque el operador ... recorre caracteres completos. == frente a ===, y la verdad según JavaScript

=== (igualdad estricta) compara sin convertir: mismo tipo y mismo valor. == convierte los tipos siguiendo una tabla que casi nadie recuerda entera, y que produce joyas como estas (todas comprobadas):

La regla: usa siempre === y !==. La única excepción aceptada es x == null, que es true justo para null y undefined y nada más (ni 0 ni ""), una forma compacta de preguntar «¿falta este valor?».

Truthy y falsy

En un if, en un while o con !, cualquier valor se convierte en booleano. Son falsy exactamente estos: false, 0, -0, 0n, "", null, undefined y NaN. Todo lo demás es truthy, incluidos "0", " ", "false", [] y {}.

La trampa clásica está en los valores por defecto. a || b devuelve b si a es falsy, así que confunde «no me lo han dado» con «me han dado un 0». El operador ?? (nullish coalescing) solo recurre al valor por defecto con null o undefined: 0 || 1 es 1, pero 0 ?? 1 es 0. Su pariente ?. (encadenamiento opcional) lee una propiedad solo si lo de la izquierda existe: undefined?.x da undefined en vez de un TypeError.

Síntoma: un parámetro que puede valer 0 (velocidad, retraso, opacidad, un ángulo inicial, la coordenada x del ratón en el borde) se ignora y se usa el valor por defecto.

Causa: el valor por defecto se escribió con ||, como en const velocidad = opciones.velocidad || 1. Como 0 es falsy, 0 || 1 da 1. Lo mismo pasa con if (x) cuando x puede ser 0 legítimamente.

Solución: opciones.velocidad ?? 1, o un parámetro con valor por defecto, function animar({ velocidad = 1 } = {}), que también solo actúa con undefined. Y compara explícitamente: if (x !== undefined).

Objetos y referencias

Una variable que contiene un objeto no contiene el objeto: contiene una referencia a él, como una dirección. Asignar copia la referencia, no el objeto:

  1. Se crea un objeto en memoria y a guarda una referencia a él.
  2. No se copia nada: b es otra referencia al mismo objeto. A esto se le llama aliasing: dos nombres para una sola cosa.
  3. Modificar a través de b modifica el objeto que también ve a.
  4. === entre objetos compara identidad (¿es el mismo objeto?), no contenido. Dos objetos iguales en contenido son distintos.
  5. Una función recibe una copia de la referencia: puede modificar el objeto del que llama (aunque no puede hacer que la variable del que llama apunte a otro objeto).

Las copias también engañan. El spread ({ ...a }) y Object.assign hacen copias superficiales: copian el primer nivel, pero los objetos anidados siguen compartidos. Lo comprobé: con a = { pos: { x: 1 } } y b = { ...a }, cambiar b.pos.x cambió a.pos.x. structuredClone(a) hace una copia profunda. Y Object.freeze también es superficial: congela el primer nivel (asignar lanza TypeError: Cannot assign to read only property 'x'… en modo estricto), pero los objetos de dentro se pueden seguir modificando.

Lo que se ve. Un único punto que cruza el lienzo en línea recta (y reaparece por el lado contrario gracias al mod), no una explosión de cien. La consola lo confirma: particulas[0].pos === particulas[99].pos es true.

Por qué. pos: origen no copia el objeto origen: guarda en cada partícula una referencia al mismo objeto. Las cien partículas comparten una sola posición. En cada frame, cada partícula le suma su velocidad a esa posición compartida, así que el punto avanza la suma de las cien velocidades. Esa suma es siempre la misma, de ahí la línea recta; y como las velocidades aleatorias se compensan solo en parte, el punto va bastante deprisa.

La corrección (botón «Ver solución»): crear un objeto nuevo por partícula, pos: { x: origen.x, y: origen.y }. La consola pasa a decir false y aparece la explosión. La misma trampa, en versión compacta: new Array(100).fill({ x: 0, y: 0 }) rellena el array con cien referencias al mismo objeto (lo comprobé: al mover el primero se movían todos). Para objetos independientes: Array.from({ length: 100 }, () => ({ x: 0, y: 0 })), donde la función se llama una vez por elemento.

Síntoma: muchos objetos que deberían ser independientes se mueven, cambian de color o reaccionan todos a la vez, como si fueran uno.

Causa: comparten un objeto por referencia: se creó una vez y se asignó a todos (pos: origen, .fill({…}), un objeto de configuración reutilizado y modificado).

Solución: crea un objeto nuevo por elemento (Array.from({ length: n }, () => ({…})), { ...obj } si es plano, structuredClone si tiene anidados). Para comprobarlo: a.pos === b.pos debe ser false.

Tres detalles que muerden:

  • reduce sin valor inicial falla con un array vacío: TypeError: Reduce of empty array with no initial value. Pon siempre el segundo argumento.
  • Los huecos: new Array(3) crea un array de longitud 3 sin elementos, y map se salta los huecos, así que new Array(3).map((_, i) => i) sigue siendo un array de tres huecos. Usa Array.from({ length: 3 }, (_, i) => i).

Y un apunte que conecta con el final de la lección: map y filter crean arrays nuevos en cada llamada. En el código de inicialización da igual; dentro de un bucle que se ejecuta 60 veces por segundo sobre miles de partículas, es basura que el recolector tendrá que limpiar.

Funciones y closures

Hay tres formas de crear una función, y se diferencian en detalles que importan:

  1. Una declaración sube entera con el hoisting: se puede llamar antes de su línea. lerp (interpolación lineal) la usarás en todo el módulo 2.
  2. Una expresión: la función es un valor asignado a una variable, y solo existe a partir de esa línea. (Es el smoothstep de GLSL, por cierto; lo verás en la lección 3.4.)
  3. Una flecha: más corta, y con una sola expresión, sin llaves, la devuelve sin return. Además, no tiene this ni arguments propios: usa los del sitio donde se escribió. Enseguida veremos por qué eso es justo lo que quieres en un bucle de animación.
  4. Parámetros con valor por defecto (solo se aplica si llega undefined) y parámetros rest (...resto recoge los sobrantes en un array).
  5. Las funciones son valores: se pasan como argumento. Aquí le pasamos frame (sin paréntesis: la función, no su resultado) al navegador para que la llame en el próximo fotograma.

Closures: funciones con memoria

Una función recuerda las variables del ámbito donde se creó, aunque ese ámbito ya haya terminado. A esa combinación de función más variables recordadas se le llama closure. Es la forma natural de guardar el estado de una animación sin variables globales:

  1. Estado privado: estas variables solo existen dentro de crearCronometro. Nadie de fuera puede leerlas ni estropearlas.
  2. Devolvemos una función creada aquí dentro. Se lleva consigo el acceso a inicio y vueltas.
  3. La primera vez que se llama, fija el instante inicial. Las siguientes, ya no. (Comparamos con === null y no con !inicio porque un instante 0 sería falsy: el bestiario de antes.)
  4. Cuando crearCronometro termina, sus variables no se destruyen: la función devuelta las mantiene vivas. Cada llamada a crearCronometro() crea un juego nuevo de variables, así que puedes tener varios cronómetros independientes.

Las closures capturan variables, no valores. El experimento clásico: crear tres funciones en un bucle que devuelven el contador. Con for (var i …) las tres devolvieron [3, 3, 3]; con for (let j …), [0, 1, 2]. Con var hay una sola variable i para todo el bucle, y cuando las funciones se ejecutan ya vale 3; con let, cada vuelta del bucle crea una variable nueva.

¿Qué imprime este código?

  • var 0, var 1, var 2, let 0, let 1, let 2
    Eso pasaría si las closures capturaran el valor de i en cada vuelta. Capturan la variable, y con var solo hay una para todo el bucle.
  • var 3, var 3, var 3, let 0, let 1, let 2
    Correcto. Los setTimeout se ejecutan después de que termine todo el código (lección 1.5). Para entonces, la única variable i vale 3. Con let, cada vuelta tiene su propia variable j, y cada closure recuerda la suya.
  • var 2, var 2, var 2, let 0, let 1, let 2
    El bucle termina cuando i < 3 es falso, es decir, cuando i ya vale 3, no 2: el último i++ se ejecuta antes de la comprobación que corta el bucle.

Ejemplo 1.3.2 — Un bucle de animación sin variables globales

Queremos una función crearAnimacion(canvas) que devuelva un objeto con iniciar() y parar(), y que guarde todo su estado (tiempo inicial, identificador del frame pendiente, fotogramas dibujados) en una closure. Así podremos tener varias animaciones en la misma página sin que se pisen.

El estado. inicio, pendiente y fotogramas se declaran dentro de crearAnimacion. Las funciones frame, iniciar y parar se crean ahí también, así que las tres ven las mismas variables, y nadie más las ve. Las dos animaciones son dos llamadas distintas, con dos juegos de variables distintos: parar una no afecta a la otra.

El tiempo. requestAnimationFrame llama a frame con un argumento: el instante del fotograma en milisegundos (el mismo reloj que performance.now()). Guardamos el primero en inicio y calculamos t como la diferencia en segundos. Calcular la posición a partir del tiempo transcurrido, y no sumando un poco en cada frame, hace que la velocidad no dependa de los fotogramas por segundo de tu pantalla; lo verás a fondo en la lección 2.3.

Parar. requestAnimationFrame devuelve un número que identifica la petición; cancelAnimationFrame(id) la anula. Por eso guardamos pendiente en cada frame: siempre contiene la petición que está por llegar. Ponerlo a 0 al parar permite que iniciar() sepa si ya hay una animación en marcha (el identificador nunca es 0) y no arranque dos bucles a la vez, que es el origen de muchas animaciones que «van el doble de rápido».

Desestructuración y spread

La última línea es un patrón muy común para configurar cosas: la función recibe un objeto y lo desestructura con valores por defecto, así puedes llamar a crearParticula({ vida: 3 }) sin acordarte del orden de los parámetros. El = {} final permite llamarla sin argumentos.

Math.max(...valores) pasa cada elemento como un argumento, y el número de argumentos tiene un límite que depende del motor y de la memoria de la pila. En mi Chrome, con 100 000 elementos funcionó y con 200 000 lanzó RangeError: Maximum call stack size exceeded. Con arrays grandes (por ejemplo, los vértices de una malla), usa un bucle o reduce.

Clases, lo justo: una Particula

Una clase es una plantilla para crear objetos con la misma forma y los mismos métodos. Es lo que usarás para las partículas, los muelles y los objetos de escena del curso:

  1. Campo estático: pertenece a la clase, no a cada objeto. Se lee como Particula.creadas.
  2. Campo privado: el # forma parte del nombre y solo el código de dentro de la clase puede leerlo. Desde fuera, p.#vida es un error de sintaxis.
  3. El constructor se ejecuta con new. this es el objeto que se está creando; cada asignación le añade una propiedad propia.
  4. Un método. Todas las partículas comparten una única copia de la función (vive en Particula.prototype); lo que cambia es el this con que se llama. Dentro, una integración elemental: la gravedad (300 px/s²) cambia la velocidad y, después, la velocidad ya actualizada mueve la posición. Ese orden tiene nombre, Euler semi-implícito, y en la lección 2.5 verás por qué importa tanto: con el orden contrario, lo que oscila acaba explotando.
  5. Un getter: se lee como una propiedad (p.viva, sin paréntesis), pero ejecuta código.
  6. Sin new, una clase no se puede llamar: Particula() lanza TypeError: Class constructor Particula cannot be invoked without 'new'. Y recuerda la TDZ: usar la clase antes de su línea es un ReferenceError.

Dos detalles más: el cuerpo de una clase siempre está en modo estricto (de ahí que this sea undefined en un método suelto), y las clases son azúcar sobre los prototipos de JavaScript: typeof Particula es "function".

Por qué este curso no usa módulos

Los módulos de JavaScript (<script type="module"> con import y export) son la forma moderna de organizar código: cada archivo tiene su propio ámbito (adiós al problema del ámbito global compartido), se cargan con defer automático y siempre en modo estricto. En tus proyectos, úsalos.

Pero este curso tiene que funcionar abriendo los archivos con doble clic, con file://, y ahí los módulos no cargan. Lo comprobé con una página que importaba un módulo vecino: con file://, Chrome se negó con este error:

La misma página servida por HTTP cargó los dos módulos sin problema. El motivo (los módulos se piden como una petición CORS, y un archivo local tiene un origen «nulo» que no puede autorizarla) lo desmontamos en la lección 1.7. Por eso aquí todo son scripts clásicos que comparten objetos globales (Curso, GLKit, Texturas) y cada archivo se protege con una función autoejecutada.

El recolector de basura y los bucles calientes

JavaScript libera la memoria solo: un recolector de basura (GC) busca de vez en cuando los objetos a los que ya no apunta nadie y los borra. Para hacerlo, V8 (el motor de Chrome) interrumpe tu código durante un momento. En la mayoría de programas no se nota; en un bucle de animación, que tiene 16,7 ms por frame a 60 Hz, cada pausa es tiempo que no dibuja.

Lo medí con una traza de rendimiento de Chrome: 20 000 partículas actualizadas durante 300 frames, primero creando dos objetos nuevos por partícula y frame (const d = { x: …, y: … } y pos[i] = { x: …, y: … }, 40 000 objetos por frame), y después modificando los mismos objetos en su sitio:

objetos nuevos cada framereutilizando
20 000 partículas: recolecciones menores en el hilo principal33 (42 ms en total)4 (las de cargar la página)
20 000 partículas: trabajo por frame (mediana)0,9 ms0,4 ms
200 000 partículas: pausas de GC29, de ellas 20 recolecciones mayores de hasta 4 ms8, solo al crear los objetos iniciales
200 000 partículas: trabajo por frame (percentil 99 / máximo)7,1 / 9,2 ms4,2 / 4,3 ms

En un M1, con 20 000 partículas, las pausas son cortas (poco más de 1 ms cada una): no es un desastre, pero es trabajo que no produce nada. Al crecer la basura, V8 pasa a recolecciones mayores y los frames lentos se alargan; en un móvil modesto, esas pausas se convierten en los típicos tirones que aparecen cada pocos segundos.

  • Crea los objetos una vez, fuera del bucle, y modifícalos en su sitio (p.x += p.vx * dt en lugar de p = { x: … }).
  • Evita map, filter, spread, desestructurar en objetos nuevos y template literals dentro del bucle por partícula.
  • Recicla en vez de crear y destruir: un pool de partículas donde las muertas se reutilizan como nuevas.
  • Para miles de elementos, guarda los datos en arrays tipados (Float32Array), sin un objeto por partícula. Es además el formato que la GPU consume directamente: lección 1.6.

Verás estas pausas en el panel Performance de DevTools como bloques «Minor GC» y «Major GC» (lección 1.7).

Ejercicios

Ejercicio 1.3.1 — Una paleta que da la vuelta

Escribe la función mod(a, n) para que devuelva siempre un valor entre 0 y n (sin incluir n), también con a negativo. El código recorre la paleta hacia atrás desde el índice 0; con tu mod, la consola debe mostrar cinco colores válidos (ningún undefined) y la tabla de comprobación debe salir entera en verde (✓).

Pista 1

Mira qué devuelve el % con -1 % 5. ¿En qué se diferencia truncar la división de redondearla hacia abajo?

Pista 2

La definición de GLSL es a − n · floor(a / n). Otra opción: si el resto sale negativo, súmale n.

Solución explicada

Con a - n * Math.floor(a / n), para a = -1, n = 5: floor(-0.2) = -1, así que el resultado es −1 − 5·(−1) = 4. El % original truncaba (−0.2 → 0) y daba −1, y paleta[-1] es undefined. Con el mod correcto, el recorrido hacia atrás desde 0 visita azul, verde, amarillo, naranja y rojo.

La versión ((a % n) + n) % n también pasa todas las pruebas: si el resto es negativo, sumarle n lo lleva al rango, y el segundo % deshace la suma cuando el resto ya era positivo. Un detalle fino: con a = -5, -5 % 5 es -0; la versión con floor da 0 positivo. Por eso la comprobación usa Object.is(r, esperado) || r === esperado, que acepta los dos ceros; si alguna vez imprimes un ángulo o un índice y ves -0, ya sabes de dónde viene.

Ejercicio 1.3.2 — El bucle que nunca llega a 1

El código quiere muestrear una curva de easing en los instantes t = 0, 0.1, 0.2, …, 1 (once muestras, la última exactamente en 1). Tiene una red de seguridad: si da más de 15 vueltas se detiene, porque sin ella se colgaría la página. Ejecútalo, entiende por qué no para, y reescríbelo para que imprima exactamente once muestras, con t terminando en 1 y valores «limpios» (0.3, no 0.30000000000000004).

Pista 1

Mira los valores de t que imprime la consola alrededor de 0.9. ¿Pasa alguna vez por 1 exactamente?

Pista 2

Los enteros pequeños son exactos en un double. ¿Y si el bucle contara con un entero y calcularas t a partir de él en cada vuelta?

Solución explicada

0.1 no es exacto en binario, y cada t += 0.1 suma un error diminuto. En Chrome, la secuencia fue 0.30000000000000004 en la tercera suma, 0.7999999999999999, 0.8999999999999999, 0.9999999999999999… y después 1.0999999999999999: salta por encima de 1 sin tocarlo, así que t !== 1 nunca es falso.

La solución cuenta con un entero, i, que es exacto y tiene un final garantizado (i <= N), y calcula t = i / N desde cero en cada vuelta. Una sola división produce el double más cercano al valor deseado, que se imprime como 0.3; acumular sumas, en cambio, arrastra el error de todas las anteriores. Es el mismo principio que en el ejemplo 1.3.2: calcula a partir de una fuente exacta (el tiempo transcurrido, un contador) en lugar de sumar poquito a poco.

Y si alguna vez necesitas un bucle con decimales, compara con < o <= más un margen, nunca con === o !==.

Ejercicio 1.3.3 — Valores por defecto que no respetan el cero

La función configurar rellena las opciones que faltan con valores por defecto. Pero cuando pides velocidad: 0 (animación en pausa), retraso: 0 u opacidad: 0, se ignoran. Arréglala para que solo use el valor por defecto cuando la opción no se ha dado. La consola debe mostrar velocidad: 0, retraso: 0, opacidad: 0, color: "tomato" en la primera línea y todos los valores por defecto en la segunda.

Pista 1

¿Qué valores hacen que a || b devuelva b? ¿Está el 0 entre ellos?

Pista 2

Hay un operador que solo mira null y undefined. Y hay otra forma, con desestructuración, que ni siquiera necesita operador.

Solución explicada

|| devuelve el lado derecho cuando el izquierdo es falsy, y 0 es falsy: 0 || 1 es 1. Hay dos arreglos equivalentes. El más directo cambia cada || por ??, que solo recurre al valor por defecto con null o undefined. La solución propuesta va un paso más allá: desestructura el parámetro con valores por defecto, que solo se aplican cuando la propiedad vale undefined. Y el = {} final permite incluso llamar a configurar() sin argumentos (con la versión original, configurar() lanzaría TypeError al leer undefined.velocidad).

Fíjate en que color no tenía el problema: un color nunca es un string vacío válido. El error solo aparece con valores que pueden ser legítimamente 0, "" o false, que en animación son muchísimos: velocidades, retrasos, ángulos, opacidades, posiciones en el borde.

Ejercicio 1.3.4 — El this perdido

La clase Animacion debería mover un cuadrado de lado a lado y contar fotogramas. Pulsa el botón: en vez de arrancar, la consola muestra un error. Arréglalo. Después escribe un método alternar() que pause y reanude sin crear nunca dos bucles a la vez, y haz que el botón lo use. Al terminar: el cuadrado se mueve, no hay errores, y cada pulsación imprime pausada o reanudada junto con los fotogramas dibujados hasta ese momento.

Pista 1

Lee el error: ¿qué es undefined? ¿Quién llama a paso, y con qué delante del punto?

Pista 2

Tienes tres arreglos para el this: una flecha en cada llamada, bind en el constructor o un campo de clase con una flecha.

Pista 3

Para pausar necesitas el identificador que devuelve requestAnimationFrame y cancelAnimationFrame. Para no crear dos bucles, usa ese mismo identificador como marca de «hay un bucle en marcha».

Solución explicada

El error. requestAnimationFrame(this.paso) entrega la función suelta. El navegador la llama sin objeto, y dentro de una clase eso deja this en undefined, así que la primera línea, this.fotogramas++, lanza TypeError: Cannot read properties of undefined (reading 'fotogramas'). Fíjate en que iniciar() sí funciona (lo llamamos como método, anim.iniciar()): el fallo llega un fotograma después, cuando es el navegador quien llama a paso. Por eso el error no apunta a la línea del botón, sino a la de dentro de paso.

El arreglo. La solución declara paso como campo de clase con una flecha. Un campo se crea en cada instancia, dentro del constructor, y una flecha toma el this del sitio donde se crea: la instancia. Da igual quién la llame después. (Contrapartida: cada instancia tiene su propia copia de la función en lugar de compartir una en el prototipo; con unas pocas animaciones no importa.)

Pausar sin duplicar bucles. this.pendiente guarda siempre el identificador del próximo frame; parar() lo cancela y lo pone a 0. iniciar() sale si ya hay uno pendiente, así que pulsar dos veces seguidas no crea dos bucles. Si creas dos bucles sin darte cuenta, cada frame se actualiza dos veces y todo lo que avance «un poco por frame» va el doble de rápido: el mismo síntoma que una pantalla de 120 Hz, que la lección 2.3 te enseña a evitar midiendo el tiempo.

  • typeof null es "object" y typeof NaN es "number". const por defecto, let si reasignas; let/const/class tienen zona muerta temporal. Los scripts clásicos comparten ámbito global: envuelve tu código.
  • Todo número es un double: 0.1 + 0.2 !== 0.3; compara con tolerancia relativa. Enteros exactos hasta 253. NaN no es igual a nada y se propaga en silencio: Number.isNaN, Number.isFinite. -0 existe (atan2 lo nota).
  • x | 0 trunca hacia cero a un entero de 32 bits: útil para aritmética entera, peligroso fuera de ±231.
  • % es un resto con el signo del dividendo (-1 % 5 === -1); el mod de GLSL es a − n·floor(a/n).
  • + con un string concatena; === siempre (salvo x == null); 0, "" y NaN son falsy: usa ?? para valores por defecto.
  • Los objetos se pasan por referencia: asignar no copia, .fill(obj) comparte, el spread es superficial.
  • Las closures guardan variables (no valores): úsalas para encapsular el estado de una animación. this depende de cómo se llama la función: pasa una flecha a requestAnimationFrame.
  • Los módulos no funcionan con file://. En los bucles calientes, no crees objetos: reutilízalos.
